# UFI-IPV6-Watchdog

**IPv6 失效自重启基带** — 后台持续检测 IPV6 是否正常的 UFI-TOOLS 插件，定期检测 IPv6 连通性，失败后自动发送基带重启指令，并在恢复后进入冷却，避免反复重启。

当随身 WiFi（中兴 U30 Air）出现 **IPv4 正常、IPv6 间歇性失效** 时，自动检测并重启基带，无需人工干预。

## 背景

我的随身 WIFI （中兴 U30 Air 全球版）在 USB 共享（RNDIS/CDC）给路由器（Cudy TR3000）场景下，常出现：

- IPv4 一直正常
- IPv6 每隔一段时间突然无法访问
- 需要手动重启一次基带，IPV6 才恢复正常

---

## 功能特性

| 功能 | 说明 |
|------|------|
| **IPv6 检测** | 只测 IPv6，不因 IPv4 异常误触发 |
| **多目标探测** | 同时 ping 阿里云、Cloudflare、Google 三个 IPv6 地址，任一可达即判定正常 |
| **连续失败阈值** | 连续 2 个检测周期全部失败才触发重启，减少误报 |
| **可靠 AT 通道** | 优先使用 `sendat -c "AT+CFUN=1,1"`，失败再回退到 `ufi_req` |
| **发送成功才冷却** | AT 真正发出并返回 OK 后才进入 30 分钟冷却；发送失败不会锁死 |
| **重启后复检** | 发送 AT 后等待 90 秒，再检测一次 IPv6 是否恢复 |
| **后台常驻** | Shell 守护进程独立运行，关闭网页不影响监控 |
| **开机自启** | 写入 `ufi_tools_boot.sh`，重启后自动拉起 |
| **一键安装/修复** | 插件内完成脚本部署、权限、自启、启动 |
| **手动重启基带** | 调用已验证的 `handleAT('AT+CFUN=1,1')` |
| **实时日志** | 检测结果、重启过程、冷却状态全部写入日志，面板可查看 |
| **标题栏状态指示** | 标题栏实时显示「IPv6 正常 / 异常」 |

## 适用设备

- 中兴 **U30 Air 全球版**
- 其他已安装 [UFI-TOOLS](https://github.com/kanoqwq/UFI-TOOLS) 且支持 `sendat` / `handleAT` 的展锐平台随身 WiFi

## 环境要求

1. 设备已安装并正常运行 **UFI-TOOLS**
2. 已开启 **高级功能**（Root Shell）
3. 能执行 `sendat` 或存在 `ufi_req`

---

## 安装方法

1. 打开 UFI-TOOLS 网页后台
2. 进入 **插件功能** 相关页面，新建/导入本仓库中的 `ufi-ipv6-watchdog.js` 插件文件
3. 刷新页面，在功能区找到 **「🌐 IPv6 断网自重启基带」**
4. 点击 **「🔧 首次安装/修复」**
5. 等待提示「部署并启动成功」

完成后会自动：

- 写入后台脚本 `/data/kano_ipv6_monitor/service.sh`
- 启动守护进程
- 配置开机自启

## 使用说明

### 面板说明

标题栏始终可见：

- **● 运行中 / ○ 已停止 / ○ 未安装** — 守护进程状态
- **IPv6 正常 / IPv6 异常 / IPv6 --** — 根据最近检测结果推断
- **▽ / △** — 展开或收起全部内容（状态、按钮、日志）

展开后可操作：

| 按钮 | 作用 |
|------|------|
| 首次安装/修复 | 重新部署脚本并启动（升级或异常时用） |
| 立即检测 | 立刻跑一轮 IPv6 检测，不等下一个周期 |
| 启动 / 停止 / 重启服务 | 控制后台守护进程 |
| 手动重启基带 | 立即发送 `AT+CFUN=1,1`（需点两次确认） |
| 设置/取消自启 | 开关开机自动启动 |
| 卸载 | 停止服务并删除相关文件（需点两次确认） |
| 刷新 | 刷新状态与日志 |
| 帮助 | 简要说明 |

日志区支持自动刷新、手动刷新、清空。

---

### 工作流程

```text
启动服务
    ↓
预检 IPv6（最多约 20 秒）
    ↓
每 5 分钟检测一次
    ├─ 三个地址任一通 → 正常，清零失败计数
    └─ 全部失败 → 失败计数 +1
            ↓
        连续 2 次失败
            ↓
        发送 AT+CFUN=1,1
            ├─ 成功 → 等待 90 秒 → 复检 → 进入 30 分钟冷却
            └─ 失败 → 不进冷却，下一轮可继续尝试
```

---

### 默认参数

| 参数 | 默认值 | 说明 |
|------|------|------|
| **检测间隔** | 300 秒（5 分钟）| 两次检测之间的间隔 |
| **失败阈值** | 2 个 | 连续多少个周期失败才重启 |
| **单次重试** | 3 次 | 一个周期内对目标的重试次数 |
| **重启后等待** | 90 秒 |  发送重启后等待多久再复检 |
| **冷却时间** | 1800 秒（30 分钟）| 成功重启后的保护期 |
| **探测目标** | 2400:3200::1 | 阿里云 |
|              | 2606:4700:4700::111 | Cloudflare |
|              | 2001:4860:4860::8888 | Google |
                  
如需修改，编辑 /data/kano_ipv6_monitor/service.sh 顶部变量后，在面板点「重启服务」即可。

---

### 注意事项

1. 仅处理 IPv6 失效。若 IPv4 也挂了，本插件不会接管（一般情况如果 IPV4 都挂了，那 IPV6 应该也挂了，所以也会重启基带）。
2. 重启基带只需 5 秒左右便可恢复网络，如果没有恢复请尝试重启设备。
4. 卸载后如需彻底清理，可手动删除：
```text
/data/kano_ipv6_monitor
/sdcard/kano_ipv6
/sdcard/ufi_tools_boot.sh 中与本插件相关的行
```

---

### 技术说明

1. 检测：ping6 / ping -6，超时 3 秒
2. 重启主路径：sendat -c "AT+CFUN=1,1"（设备实测可用）
3. 重启备用路径：ufi_req 调用本地 /api/AT（自动鉴权）
4. 手动重启：前端 handleAT('AT+CFUN=1,1')
5. 进程管理：PID 文件 + stop 标志，支持干净停止
6. 自启：追加到 UFI-TOOLS 的 ufi_tools_boot.sh
